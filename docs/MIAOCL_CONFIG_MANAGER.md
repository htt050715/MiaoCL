# MiaoCL 1.1.17 配置管理试用

Windows x64：运行 MiaoCL-1.1.17.exe，或先解压 Windows ZIP 后运行其中的 EXE。
便携运行组件会展开到 EXE 旁的 KAMUCL-runtime 目录；该兼容目录名沿用原启动器。

## 参数管理入口

在启动器选择游戏目录与实例，进入资源管理中的 MOD 参数面板。
面板内的客户端配置管理区可以浏览 SlimefunHelper、Meteor 和 Baritone 文件，
编辑 NBT、YAML、JSON 与文本配置，保存配置档，导入/导出完整配置。
好友、模块以及附加模块等内容由实际配置文件和已加载的 Meteor 注册模块决定。

游戏运行中需要通过面板安装内置 Bridge MOD，然后启动相应 Fabric 实例，
启动器才能枚举当前已加载的 Meteor 插件和参数，并执行实时同步及热重载。
已有客户端需要退出后重新启动才能加载新安装的桥接 MOD。

保存修改时可选择重启当前实例、下次启动生效或取消修改；
可热加载的配置还可以立即应用。配置档切换会尝试使用同一桥接路径热重载。
不支持热加载的插件文件和内部缓存会提示下次启动生效。
下次启动生效的草稿存放在实例的 .miaocl-configs 中，避免被运行中客户端退出保存覆盖。
检测到游戏侧对同一字段的修改时会阻止冲突覆盖；应用前会备份配置。

## 已完成验证与边界

配置管理测试覆盖保存、取消、退出合并、冲突、重启顺序、配置档还原、导入路径校验，
并对本机实例 417 个配置文件执行只读 NBT 往返检查。
桥接使用当前本地源码中的 Meteor Systems.load/save 与 SlimefunHelper 加载接口。
尚未完成真实 Minecraft 1.21.11 内的模块、好友与配置档热重载验收；
编译和启动器启动验证不能作为游戏热重载成功的证据。
